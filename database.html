Database Management Systems

Mastering MS Access for data management as per the Ugandan ICT Syllabus (Senior 3, Term 2)

Learning Outcomes (Syllabus Based)

  • Explain database concepts and identify DBMS examples (MS Access, Oracle, MySQL).
  • Identify records, fields, and data types in a database.
  • Create tables, define fields, and set appropriate data types and properties.
  • Apply validation rules, validation text, and input masks.
  • Create forms for easy data entry.
  • Query databases using operators (=, >, <, >=, <=, <>, IS NULL).
  • Generate professional reports with calculations.
  • Create a relational database with up to two tables.
  • Print database objects to required layouts.

1. Introduction to Databases & DBMS

What is a Database?

A database is an organized collection of structured data stored electronically. A Database Management System (DBMS) is software that allows users to create, manage, and interact with databases. Examples include MS Access, MySQL, Oracle, and SQL Server.

2. Getting Started with MS Access

MS Access Database Objects

A database in MS Access consists of several key objects: Tables (store data), Queries (ask questions), Forms (data entry interface), Reports (printable output).

2
Activity: Exploring MS Access Interface
  1. Launch MS Access. Select "Blank Database". Name it SchoolDB.accdb and save it.
  2. Identify the Navigation Pane on the left. Note the default "Table1".
  3. Switch between Datasheet View (data entry) and Design View (structure) using the buttons at the bottom-right of the Access window.
  4. Create a new table in Design View. Add fields: StudentID (AutoNumber), FirstName (Short Text), LastName (Short Text), DateOfBirth (Date/Time).
  5. Set StudentID as the Primary Key (right-click the row → Primary Key).
  6. Save the table as "Students". Switch to Datasheet View and enter 5 sample student records.
  7. Teacher Assessment: Observe correct creation of table, field types, and primary key.

3. Data Types, Validation & Input Masks

Ensuring Data Integrity

Validation Rules ensure data entered meets specific criteria. Input Masks control the format of data entry (e.g., phone numbers, dates).

3
Activity: Applying Validation and Input Masks
  1. Open the Students table in Design View.
  2. Select the DateOfBirth field. In the Field Properties pane (bottom), click the Validation Rule box and type: >=#1/1/2000# And <=#12/31/2010# (adjust years as appropriate).
  3. In the Validation Text box, type: "Date must be between 1/1/2000 and 12/31/2010". Save the table.
  4. Create a new field: PhoneNumber (Short Text). In the Input Mask property, click the ... button. Select "Phone Number" mask and follow the wizard.
  5. Attempt to enter an invalid date in Datasheet View to test the validation rule. Observe the error message.
  6. Teacher Assessment: Check the correct implementation of validation rules, text, and input masks.

4. Creating Data Entry Forms

Why Use Forms?

Forms provide a user-friendly interface for data entry, preventing users from accidentally modifying the underlying table structure.

4
Activity: Building a Student Entry Form
  1. Select the Students table in the Navigation Pane.
  2. Click the Create tab → Form. MS Access will automatically generate a bound form.
  3. Switch to Layout View to adjust the size and position of fields.
  4. Switch to Form View. Use the navigation buttons at the bottom to add, edit, and delete records.
  5. Add a new student using the form. Observe how the form updates the underlying table.
  6. Save the form as "frmStudents".
  7. Teacher Assessment: Evaluate the form's usability and correct binding to the table.

5. Querying the Database

What is a Query?

Queries allow you to ask questions about your data and retrieve specific records. MS Access provides a graphical Query by Example (QBE) grid.

5
Activity: Creating Queries with Operators
  1. Go to Create tab → Query Design. Add the Students table.
  2. Add the fields: FirstName, LastName, DateOfBirth.
  3. In the Criteria row under LastName, type: "Smith" (for exact match). Run the query (red exclamation mark).
  4. Using Comparison Operators:
    • In the Criteria under DateOfBirth, type: >#1/1/2005# (students born after 2005).
    • Try: <#1/1/2005# (before 2005).
    • Try: >=#1/1/2004# And <#1/1/2006# (range).
    • Find students NOT named "Smith": Use <>"Smith".
    • Find students with no phone number: Use Is Null in the PhoneNumber field.
  5. Save the query as "qryStudentsAfter2005".
  6. Extension: Create a query that counts the number of students. Use the Totals button (Σ) and change "Group By" to "Count".
  7. Teacher Assessment: Verify correct use of query operators and criteria syntax.

6. Generating Reports

Presenting Data Professionally

Reports are used to format, calculate, and print data in a readable layout.

6
Activity: Creating a Student Report
  1. Select the qryStudentsAfter2005 query in the Navigation Pane.
  2. Click Create → Report. Access generates a basic report.
  3. Switch to Layout View to group, sort, and format the report. Add a title: "Student List (After 2005)".
  4. To add a calculation (e.g., count of students): Go to Design View. In the Report Footer section, add a text box. Set its Control Source to: =Count(*).
  5. Switch to Print Preview to see the final layout. Ensure all data fits on the page.
  6. Print the report or export it as a PDF (File → Print → Print to PDF).
  7. Teacher Assessment: Assess the report's layout, grouping, and inclusion of calculated values.

7. Creating a Relational Database (2 Tables)

Understanding Relationships

A relational database links tables using a common field (Foreign Key). This prevents data duplication. E.g., one student can have many exam scores.

7
Activity: Relating Students and Exams
  1. Create a new table called Exams with fields: ExamID (AutoNumber, Primary Key), StudentID (Number), Subject (Short Text), Score (Number).
  2. Go to Database Tools tab → Relationships. Add both Students and Exams tables.
  3. Drag the StudentID field from the Students table and drop it on the StudentID field in the Exams table.
  4. In the Edit Relationships dialog, check "Enforce Referential Integrity". Click Create. A line now shows the one-to-many relationship.
  5. Enter sample exam records (e.g., StudentID 1, Subject "Math", Score 85).
  6. Create a query that joins both tables: Create → Query Design. Add both tables. Select FirstName, LastName, Subject, Score. Run the query.
  7. Teacher Assessment: Verify the correct creation of a relationship and a successful join query.

Activity of Integration

School Library Database Project

Your school library needs a database to manage books and borrowers. Create a complete MS Access database.

FINAL
Library Management System
  1. Design tables: Books (BookID, Title, Author, YearPublished, ISBN) and Borrowers (BorrowerID, FullName, Class, Phone).
  2. Create a relationship between the tables (one borrower can borrow many books).
  3. Set appropriate data types (AutoNumber, Short Text, Number, etc.) and validation rules (e.g., YearPublished between 1900 and current year).
  4. Create a form for entering new borrowers.
  5. Create a query to find all books published after 2010.
  6. Create a query to count the total number of borrowers.
  7. Create a professional report listing all books, grouped by Author.
  8. Print the report and any one query.
  9. Self-Assessment Checklist: Can you explain each object? Did you enforce referential integrity? Are your reports formatted for printing?
