Introduction to Databases

What is a Database?

A database is an organized collection of structured data stored electronically in a computer system. Databases are designed to efficiently store, retrieve, and manage large amounts of data.

What is a DBMS?

Database Management System

A Database Management System (DBMS) is software that enables users to create, manage, and interact with databases. Examples include:

  • MySQL - Open-source, popular for web applications
  • PostgreSQL - Advanced open-source, enterprise-ready
  • Microsoft SQL Server - Enterprise, integrates with .NET
  • Oracle Database - Large-scale enterprise systems
  • SQLite - Lightweight, embedded databases
  • MongoDB - NoSQL document database

Database Architecture

The Three-Level Architecture

External Level (View Level)

How users view the data - different users see different views

User 1 → View A | User 2 → View B | User 3 → View C
Conceptual Level (Logical Level)

What data is stored and the relationships between them

Tables, relationships, constraints
Internal Level (Physical Level)

How data is physically stored on storage devices

File structures, indexing, compression

Keys in Databases

Key TypeDescriptionExample
Primary Key (PK) Uniquely identifies each record in a table StudentID, EmployeeID, ProductID
Foreign Key (FK) References the primary key in another table CourseID in Enrollment table, DepartmentID in Employee table
Candidate Key Could serve as primary key (unique, not null) Email, Phone Number, National ID
Composite Key Two or more columns combined to form a unique identifier (StudentID, CourseID) in Enrollment
Alternate Key Candidate keys not chosen as primary key Email (if StudentID is PK)
Super Key Set of attributes that uniquely identifies a record {StudentID, Name} or {StudentID}

Normalization

What is Normalization?

Normalization is the process of organizing data to minimize redundancy (duplicate data) and dependency anomalies. It involves splitting tables into smaller, related tables.

Normal Forms

Normal FormRequirementExample Violation
1NF (First Normal Form) No repeating groups or arrays; each cell contains atomic (single) value A student having multiple phone numbers in one field
2NF (Second Normal Form) In 1NF + no partial dependencies (all non-key attributes depend on entire primary key) In a composite key table, an attribute depends on only part of the key
3NF (Third Normal Form) In 2NF + no transitive dependencies (non-key attributes depend only on the primary key) Student table containing Department Head name (depends on Department, not Student)
BCNF Stricter version of 3NF Every determinant is a candidate key

Example: Unnormalized vs Normalized

-- UNNORMALIZED (Problems: repeating groups, redundancy)
Customer (CustomerID, Name, Address, Order1, Order2, Order3)

-- 1NF (Remove repeating groups)
Customer (CustomerID, Name, Address)
Orders (OrderID, CustomerID, Product)

-- 2NF (Remove partial dependencies)
Customer (CustomerID, Name, Address)
OrderItems (OrderID, ProductID, Quantity)
Products (ProductID, Name, Price)

-- 3NF (Remove transitive dependencies)
Employee (EmployeeID, Name, DepartmentID)
Department (DepartmentID, DeptName, ManagerID)

SQL Fundamentals

What is SQL?

SQL (Structured Query Language) is the standard language for managing and querying relational databases. It allows you to create, read, update, and delete data.

Basic SQL Statements

CREATE TABLE

CREATE TABLE Students (
    StudentID INT PRIMARY KEY,
    Name VARCHAR(100) NOT NULL,
    Email VARCHAR(100) UNIQUE,
    DOB DATE,
    DepartmentID INT
);

SELECT (Query Data)

SELECT * FROM Students;
SELECT Name, Email FROM Students WHERE DepartmentID = 1;
SELECT AVG(Grade) AS AverageGrade FROM Enrollments WHERE CourseID = 'CS101';

INSERT (Add Data)

INSERT INTO Students (StudentID, Name, Email, DepartmentID)
VALUES (1, 'John Smith', 'john@school.edu', 2);

UPDATE (Modify Data)

UPDATE Students
SET Email = 'john.smith@school.edu'
WHERE StudentID = 1;

DELETE (Remove Data)

DELETE FROM Students WHERE StudentID = 1;

JOIN (Combine Tables)

SELECT Students.Name, Courses.Title, Enrollments.Grade
FROM Students
INNER JOIN Enrollments ON Students.StudentID = Enrollments.StudentID
INNER JOIN Courses ON Enrollments.CourseID = Courses.CourseID;

Database Security

Protecting Database Data

  • Authentication: Verify user identity (username/password)
  • Authorization: Control what users can do (GRANT/REVOKE permissions)
  • Encryption: Protect data at rest and in transit
  • Backups: Regular database backups for recovery
  • Auditing: Track database access and changes
  • SQL Injection Prevention: Use parameterized queries

SQL Injection Example

-- VULNERABLE CODE (DO NOT USE)
username = "' OR '1'='1"; -- Bypasses authentication
SELECT * FROM Users WHERE Username = '' OR '1'='1';

-- SAFE (Parameterized Query)
PREPARE stmt FROM 'SELECT * FROM Users WHERE Username = ?';
EXECUTE stmt USING @username;
