Database Management Systems Overview

A Database Management System (DBMS) is software that enables the creation, manipulation, and administration of databases. It serves as an interface between users, applications, and the physical database stored on disk.

What is a Database?

A database is an organized collection of structured data stored in a computer system and accessed electronically. It contains:

  • Tables: Organized data in rows and columns
  • Records: Individual rows in a table
  • Fields: Individual columns in a table
  • Relationships: Links between tables
  • Indexes: Mechanisms to speed up data retrieval

Advantages of Using a DBMS

  • Data organization and efficient storage
  • Data security and access control
  • Data consistency and integrity
  • Multi-user access and concurrent operations
  • Backup and recovery capabilities
  • Query optimization and performance

Core Concepts

Entity-Relationship Model (ER Model)

The ER model is used to design databases by identifying entities (objects), their attributes, and relationships.

  • Entity: A thing or object (e.g., Student, Course)
  • Attribute: A property of an entity (e.g., StudentID, Name)
  • Relationship: Association between entities (e.g., Enrolls)

Keys in Databases

Key Type Description Example
Primary Key Uniquely identifies each record StudentID
Foreign Key References primary key in another table CourseID in Enrollment table
Candidate Key Could serve as primary key Email if unique
Composite Key Multiple fields combined as key StudentID + CourseID

Types of Databases

Relational Databases

Most Common Type: Data organized in tables with rows and columns. Uses SQL for queries.

Examples: MySQL, PostgreSQL, Microsoft SQL Server, Oracle

NoSQL Databases

Non-Relational: Flexible schema, stores data in documents, key-value pairs, or graphs.

Examples: MongoDB, Cassandra, Redis, CouchDB

Other Database Types

  • Hierarchical Databases: Tree-like structure
  • Network Databases: Complex relationship structure
  • Object-Oriented Databases: Store objects directly
  • Graph Databases: Optimize for relationships

Database Design Principles

Normalization

Normalization is the process of organizing data to minimize redundancy and dependency anomalies.

Normal Forms:

  • 1NF (First Normal Form): Eliminate repeating groups
  • 2NF (Second Normal Form): Remove partial dependencies
  • 3NF (Third Normal Form): Remove transitive dependencies
  • BCNF (Boyce-Codd Normal Form): Stricter version of 3NF

Data Integrity

  • Entity Integrity: Primary key cannot be null
  • Referential Integrity: Foreign keys must reference valid primary keys
  • Domain Integrity: Values within valid domain/type
  • User-Defined Integrity: Custom business rules

SQL Basics

Common SQL Operations

SELECT - Retrieve Data

SELECT column1, column2 FROM table_name WHERE condition;

INSERT - Add Data

INSERT INTO table_name (column1, column2) VALUES (value1, value2);

UPDATE - Modify Data

UPDATE table_name SET column1 = value1 WHERE condition;

DELETE - Remove Data

DELETE FROM table_name WHERE condition;

JOIN Operations

JOINs combine rows from two or more tables based on a common column:

  • INNER JOIN: Returns matching records
  • LEFT JOIN: All left table records + matching right
  • RIGHT JOIN: All right table records + matching left
  • FULL JOIN: All records from both tables
Best Practice: Always use proper indexing and normalize your database for optimal performance.
